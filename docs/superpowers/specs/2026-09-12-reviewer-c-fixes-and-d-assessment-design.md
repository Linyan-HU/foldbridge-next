# 评审 C 类修复与 D 类范围评估设计

## 目标

第一批工作优先完成评审意见中的 C 类问题，使每条意见都有可复现、可验证、可写入 rebuttal 的处理结果。同时只评估 D 类新增功能，不在本批实现。

本批采用最小闭环方案：修复评审明确指出的行为，不增加无关功能，不恢复已经停用的 RMDB 原始反应性热图，也不重新公开已经不被页面使用的 RDAT 文件。

## 工作范围

### C1.5 响应式布局

针对主站关键路径和 Case 页面进行窗口尺寸复现与修复：Home、Search、Entry 列表、Entry Case 外层页面及 Case 内嵌 Workbench。

验收尺寸为 1440×900、1024×768、768×1024 和 390×844。每个尺寸下应满足：

- 页面不出现由固定宽度造成的整体横向滚动。
- 导航、搜索框、筛选控件、Profile 下拉框和可视化面板不被裁切或相互覆盖。
- Case 外层页面和内嵌 Workbench 保持现有高度同步机制，不重新引入双重纵向滚动条。
- 数据表和确实需要横向空间的局部可视化可以在自身容器内滚动。

修复只调整造成问题的固定宽度、网格断点和容器溢出规则，不重做全站视觉系统。

### C1.6 Extended PDB ID 搜索

在进入 Pagefind 前规范化用户查询。对于已有四字符 PDB ID 的扩展写法，大小写不敏感地将 `pdb_0000XXXX` 映射到 `XXXX`，并保留用户在输入框中看到的原始查询。

验收样例：

- `pdb_00001ddy` 与 `1DDY` 返回完全相同的结果集合和数量。
- 普通文本查询及四字符 PDB ID 的既有行为不变。
- 不符合 `pdb_0000XXXX` 形式的查询不做猜测性截断。
- 数据集中尚不存在的未来 Extended PDB ID 只进行精确搜索，不伪造四字符别名。

查询规范化封装为独立纯函数，并使用单元测试覆盖大小写、空格、合法格式和相似但非法的输入。

### C1.7 VARNA 放大后的浏览

保留现有 `+`、`-` 和 `1:1` 控件，只修正 VARNA 视口的溢出行为。缩放大于 100% 后，视口提供浏览器原生横向和纵向滚动，可通过滚轮、触控板、触摸或键盘移动到超出可见区域的结构部分。

本批不增加拖拽平移、缩略导航图或新的工具栏。

### C1.8 Technique 筛选反馈

保留现有 SHAPE、DMS、SHAPE-based methods 和 DMS-based methods 筛选语义。点击筛选条件后：

- 更新 Profile 下拉列表中的可见选项。
- 在筛选控件旁显示 `匹配 N 个 Profile；请在 Profile 下拉列表中选择`。
- 零命中时显示 `无匹配 Profile`。
- 清空全部条件时显示全部 Profile，并提示总数。

筛选不自动切换当前 Profile，不增加确认按钮，不刷新页面，也不自动更新 1D、2D 或 3D 视图。

状态区域使用 `aria-live="polite"`，让辅助技术也能获得反馈。

### C1.9 废弃 RDAT 请求

`PDB130_DMS_0000.rdat` 不属于当前页面需要公开提供的资源。本批不恢复该文件，也不添加替代下载地址。

验收目标是当前 8SQ9 Case 页面及共享 Workbench 不请求该 RDAT URL、不渲染已停用的 RMDB 原始反应性热图、不显示相关 404 错误。保留未调用的旧实现也必须受到回归测试约束，确保初始化和 Profile 切换路径均不会触发请求；若存在缓存问题，则通过版本化静态资源或明确的缓存失效处理解决。

### C3.2 反应性状态三区分

反应性显示采用用户确认的 A 方案，先按原始值分类，再进行正值归一化：

- 缺失或未映射：原始值不是有限数值，使用中性灰色；1D 和 2D 支持时使用灰色纹理，3D 使用等价的实心灰色。
- 实测非正值：原始值为有限数值且小于或等于 0，使用淡蓝色。
- 正值：原始值大于 0，继续使用当前基于正值 P95 上限的白—黄—红连续色带。

颜色语义应同步应用到当前 Profile 的 1D 轨道、2D VARNA 和 3D Mol* 显示，并更新图例和计数文案。悬停和选中描边可以覆盖边框，但不改变底色所表达的反应性状态。

该改动不作用于 E/F 接触矩阵，也不恢复 RMDB 原始反应性热图。

## 组件边界

- 主站搜索：在 `src/search` 内增加查询规范化和测试，不修改 Pagefind 文档数量及 Case 路由。
- 主站响应式：只修改当前主站样式和必要的 Case 外层嵌入规则。
- Case Workbench：修改共享的未版本化与当前版本化 JS/CSS 资源，保持两份资源行为一致。
- 纯逻辑：将反应性状态分类、筛选状态文案等尽量提取为无 DOM 依赖的函数，便于精确测试。
- 数据：不改 Profile 数值、Case 资产、RDAT 数据或 E/F 矩阵数据。

## 错误处理

- Extended PDB ID 规范化只接受严格格式；其他输入原样交给 Pagefind。
- Technique 元数据不可用时保持现有降级行为，并明确提示元数据不可用，不显示虚假的命中数。
- VARNA 未加载或 SVG 不完整时不创建误导性的滚动状态。
- 反应性原始值缺失时保持缺失状态，不将其强制转换为 0。
- 已停用的 RDAT 功能不得在失败后反复请求或向用户显示无意义的恢复入口。

## 验证策略

### 自动化测试

- Extended PDB ID 查询规范化及 `pdb_00001ddy` / `1DDY` 等价性。
- Technique 筛选的命中数、零命中、清空条件和元数据不可用状态。
- 反应性三状态分类、计数、颜色语义及正值 P95 归一化不回归。
- 共享未版本化与版本化 Case 资源一致性。
- 8SQ9 初始化和 Profile 切换不调用 RDAT 获取路径。
- 现有搜索、Case 联动、下载和 E/F 矩阵测试继续通过。

### 浏览器验收

- 在 4 个目标视口检查主站关键路径和 8SQ9 Case 页面。
- 使用 `pdb_00001ddy` 与 `1DDY` 比较结果集合。
- 在含多个 Profile 的 Case 中点击 Technique 筛选，确认只更新列表与命中提示。
- 放大 VARNA 后滚动到四个方向的边缘，再恢复 `1:1`。
- 在包含缺失值、非正值和正值的 Profile 中核对 1D、2D、3D 与图例。
- 监控网络请求和控制台，确认没有 `PDB130_DMS_0000.rdat` 请求或 404。

### 交付边界

本批先完成源码、测试和本地浏览器验证。Git push、GitHub Pages 发布及 `/Volumes/tianyi/Server/public` 权威静态源替换需要单独明确授权；不能以本地测试通过代替线上完成。

## D 类评估

本批输出 D3.3、D3.4 和 D3.6 的范围评估，不写实现代码。

### D3.3 几何参数

盘点现有 Case 和 linked-view 数据是否已包含糖环构象、碱基堆积类型及可靠来源。报告覆盖率、缺失率、生成依赖、前端展示位置和验证方法，再判断哪些参数适合下一批加入。

### D3.4 热图下载与交互

分别评估：

- 现有 E/F 接触矩阵的交互能力和可下载格式。
- 当前 Profile 反应性视图可否导出 PNG、SVG、CSV 或 JSON。

评估不得把已经停用的 RMDB 原始反应性热图重新纳入方案。报告应明确用户所说的“热图”对应哪一类数据，再给出实现建议。

### D3.6 多 Profile 比较与统计

将需求拆成 3 层分别评估：

1. 多 Profile 并排或叠加可视化。
2. 描述性统计和相关性。
3. 显著性检验。

重点核对 Profile 是否具有同一序列坐标、相同或不同探针、重复实验身份、样本量及误差字段。没有足够实验设计信息时，不承诺显著性检验。
